Key Architectural Guidelines:
-----------------------------
1. Central Bootstrap Initializer (config/bootstrap.php):
   Avoid scattering `session_start()` and database includes with deep relative 
   paths (e.g., `../../../../config/db_connect.php`). Define `APP_ROOT` once:
   
   ```php
   <?php
   // config/bootstrap.php
   define('APP_ROOT', dirname(__DIR__));

   // Load .env
   if (file_exists(APP_ROOT . '/.env')) {
       $env = parse_ini_file(APP_ROOT . '/.env');
       foreach ($env as $key => $val) {
           $_ENV[$key] = $val;
       }
   }

   define('BASE_URL', $_ENV['APP_URL'] ?? '/daph-ep-mis/');

   require_once APP_ROOT . '/config/constants.php';
   require_once APP_ROOT . '/config/db_connect.php';
   ```

2. Standardize Static Asset Paths:
   Replace fragile dynamic relative path logic (`str_repeat('../', $diff)`) with 
   the centralized `BASE_URL`:
   `<link href="<?= BASE_URL ?>assets/css/bootstrap.min.css" rel="stylesheet">`

3. Separate UI Modals from Data Models:
   Files inside `pages/modules/veterinary/models/` are actually Bootstrap HTML modals. 
   Move them to `includes/modals/` or keep them cleanly marked as `views/modals/` 
   so backend developers do not confuse them with database entities.

4. Consolidate Duplicate Business Logic:
   Avoid writing the exact same SQL queries for employee onboarding across 
   separate module processors (`hr`, `pd`, `veterinary`, `sms`, `training`, `farm`).
   Centralize common employee persistence and validation into `app/Services/EmployeeService.php`.

2. ENVIRONMENT CONFIGURATION & DATABASE CREDENTIALS (.env)
================================================================================

Never commit database passwords or sensitive API keys into source control.

Step 1: Create a .env.example (Safe to commit to Git)
---------------------------------------------------
# Application Environment
APP_ENV=production
APP_DEBUG=false
APP_URL=https://mis.daph.ep.gov.lk/

# Database Credentials
DB_HOST=localhost
DB_PORT=3306
DB_NAME=daph_mis_prod
DB_USER=daph_app_user
DB_PASS=p@$$w0rd_S3cur3_2026

# Session Security
SESSION_LIFETIME=14400

Step 2: Add .env and Temporary Files to .gitignore
-------------------------------------------------
Ensure the root .gitignore contains:
.env
/storage/logs/*.log
/storage/uploads/*
!/storage/uploads/.gitkeep
*.sql
*.xlsx
*.docx
server_db_constants.php

Step 3: Safe Environment Loader in config/db_connect.php
--------------------------------------------------------
```php
<?php
require_once __DIR__ . '/constants.php';

$db_host = $_ENV['DB_HOST'] ?? DB_HOST;
$db_user = $_ENV['DB_USER'] ?? DB_USER;
$db_pass = $_ENV['DB_PASS'] ?? DB_PASS;
$db_name = $_ENV['DB_NAME'] ?? DB_NAME;

$mysqli = new mysqli($db_host, $db_user, $db_pass, $db_name);

if ($mysqli->connect_error) {
    error_log("Database connection failure: " . $mysqli->connect_error);
    // Never output raw connection errors (passwords/paths) to the live screen
    die("A temporary system error occurred. Please contact technical support.");
}

$mysqli->set_charset("utf8mb4"); // Critical for Sinhala/Tamil characters
```

Step 4: Least-Privilege Database Account
----------------------------------------
Do not connect using MySQL `root` in production. Create a dedicated application user:
```sql
CREATE USER 'daph_app_user'@'localhost' IDENTIFIED BY 'STRONG_RANDOM_PASSWORD';
GRANT SELECT, INSERT, UPDATE, DELETE ON daph_mis_prod.* TO 'daph_app_user'@'localhost';
FLUSH PRIVILEGES;
```

3. PHP ERROR REPORTING & SECURE LOGGING
================================================================================

In production, never display raw PHP errors, warnings, or database stack traces to 
end users. Stack traces reveal table names, SQL syntax, and server directory paths.

1. Server Level: php.ini Directives (Recommended)
-------------------------------------------------
```ini
display_errors = Off
display_startup_errors = Off
log_errors = On
error_reporting = E_ALL & ~E_DEPRECATED & ~E_STRICT
error_log = /var/www/daph-ep-mis/storage/logs/php_errors.log
```

2. Application Level: Centralized Error Handling in config/bootstrap.php
-----------------------------------------------------------------------
```php
<?php
$is_debug = filter_var($_ENV['APP_DEBUG'] ?? false, FILTER_VALIDATE_BOOLEAN);

if ($is_debug) {
    ini_set('display_errors', '1');
    ini_set('display_startup_errors', '1');
    error_reporting(E_ALL);
} else {
    // Production Mode: Suppress browser output and write to private log file
    ini_set('display_errors', '0');
    ini_set('display_startup_errors', '0');
    ini_set('log_errors', '1');
    ini_set('error_log', APP_ROOT . '/storage/logs/php_errors.log');
    error_reporting(E_ALL & ~E_DEPRECATED & ~E_STRICT);
}
```

4. FILE & FOLDER PERMISSIONS (LINUX / APACHE / NGINX)
================================================================================

Apply the Principle of Least Privilege to server files:

Directory / File Type            Permissions  Owner:Group        Purpose
-------------------------------  -----------  -----------------  -----------------------------------
Standard PHP scripts & files     644          deployer:www-data  Readable by web server, writable by deployer
Standard directories             755          deployer:www-data  Traversible and readable
.env configuration file          640 or 600   deployer:www-data  Strictly restricted from public access
Uploads directory (storage/uploads) 775       www-data:www-data  Writable for avatars/docs, execution disabled
Logs directory (storage/logs)    775          www-data:www-data  Writable for application log files

Shell Setup Commands (Ubuntu/Apache):
------------------------------------
```bash
cd /var/www/daph-ep-mis
sudo chown -R deployer:www-data .
sudo find . -type d -exec chmod 755 {} \;
sudo find . -type f -exec chmod 644 {} \;
sudo chmod 640 .env
sudo chmod -R 775 storage/logs storage/uploads
```

Uploads Execution Blocker (storage/uploads/.htaccess):
-----------------------------------------------------
Prevent uploaded avatars and documents from executing as PHP scripts:
```apache
<FilesMatch "\.(php|phtml|php3|php4|php5|php7|php8|phps|phar|inc|pl|cgi)$">
    Order Allow,Deny
    Deny from all
</FilesMatch>
Options -Indexes -ExecCGI
```

5. SECURITY HEADERS & SESSION HARDENING
================================================================================

1. Session Cookie Security (Before session_start()):
---------------------------------------------------
Always configure session attributes prior to calling `session_start()`:
```php
if (session_status() === PHP_SESSION_NONE) {
    ini_set('session.use_only_cookies', '1');
    ini_set('session.use_strict_mode', '1');

    $is_https = (!empty($_SERVER['HTTPS']) && $_SERVER['HTTPS'] !== 'off') 
                || (isset($_SERVER['SERVER_PORT']) && $_SERVER['SERVER_PORT'] == 443);

    session_set_cookie_params([
        'lifetime' => 14400,        // 4 hours expiration
        'path'     => '/',
        'domain'   => '',
        'secure'   => $is_https,    // Transmit cookie only over HTTPS
        'httponly' => true,         // Mitigate XSS session cookie theft
        'samesite' => 'Lax'         // Mitigate Cross-Site Request Forgery (CSRF)
    ]);
    session_start();
}
```

2. Session Fixation Defense:
----------------------------
Regenerate the session ID immediately upon successful login in `auth/login_process.php`:
```php
session_regenerate_id(true);
$_SESSION['user_id'] = $user['id'];
$_SESSION['user_category'] = $user_category;
```

3. Production HTTP Security Headers (.htaccess in Root):
-------------------------------------------------------
```apache
<IfModule mod_headers.c>
    # Prevent clickjacking in iframes
    Header always set X-Frame-Options "SAMEORIGIN"

    # Prevent MIME-sniffing
    Header always set X-Content-Type-Options "nosniff"

    # Referrer policy to protect internal URL structures
    Header always set Referrer-Policy "strict-origin-when-cross-origin"

    # Restrict unneeded browser hardware features
    Header always set Permissions-Policy "geolocation=(), microphone=(), camera=()"

    # Enforce HTTPS (Enable once SSL certificate is active)
    # Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains; preload"
</IfModule>

# Disable directory browsing across the entire site
Options -Indexes
```

6. PRE-LAUNCH OPERATIONAL CHECKLIST
================================================================================

[ ] Purge Sensitive Root Files:
    Remove all *.sql, *.xlsx, and server_db_constants.php from the public web root.

[ ] Database Least-Privilege Account:
    Replace `root` with a dedicated production MySQL user granted only:
    GRANT SELECT, INSERT, UPDATE, DELETE ON daph_mis_prod.* TO 'daph_app_user'@'localhost';

[ ] Environment Configuration (.env):
    Create production .env (chmod 640), confirm .env is present in .gitignore.

[ ] Error Reporting Disabled:
    Verify `display_errors = Off` in php.ini and confirm logs write to `storage/logs/php_errors.log`.

[ ] Storage Upload Protection:
    Verify `storage/uploads/.htaccess` blocks script execution (.php, .phar, etc.).

[ ] Disable Directory Indexing:
    Confirm `Options -Indexes` is active in the root .htaccess.

[ ] SSL / HTTPS Enforcement:
    Install valid SSL certificates (e.g., Let's Encrypt / Certbot) and redirect HTTP to HTTPS.

[ ] Session Hardening:
    Confirm `httponly=true`, `secure=true` (over HTTPS), `samesite=Lax`, and `session_regenerate_id(true)`.

[ ] Automated Daily Database Backups:
    Configure a daily cron job to dump and compress the database to an offsite/private directory:
    0 2 * * * mysqldump -u daph_app_user -p'PASSWORD' daph_mis_prod | gzip > /backups/db/daph_$(date +\%F).sql.gz

[ ] Asset Cache Busting:
    Append version parameters to CSS/JS tags (e.g. `bootstrap.min.css?v=1.0.1`) 
    so users immediately receive updated assets upon new deployments.
